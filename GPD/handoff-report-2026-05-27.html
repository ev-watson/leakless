What Was Debugged

  1. The original DDP crash reported unused parameters during the first training step.
  2. Clearing tlogs/* ruled out old model checkpoints as the direct source. The log said .fit(ckpt_path="last") found no last checkpoint.
  3. The earlier debug launch had multiple visible GPUs but only one Slurm task, so Lightning initialized with MEMBER: 1/1. That was not a valid one-process-per-GPU DDP topology.
  4. Changing to one task per GPU fixed the rank topology, but --gpus-per-task=1 was rejected by Expanse because that system expects an explicit --gpus request.
  5. --ntasks-per-gpu=1 produced correct ranks, but Lightning rejected the derived SLURM_NTASKS=2 and required --ntasks-per-node instead.
  6. The working direction is to keep explicit --gpus=2 or --gpus=4, use --ntasks-per-node=2 or --ntasks-per-node=4, and bind one task per GPU with --tres-bind=gres/gpu:single:1.

Important Decisions

  • No find_unused_parameters=True workaround. It hides the symptom and does not explain the graph or launch mismatch.
  • Run HRM architecture with MSE first. The project should evaluate the updated architecture before adding auxiliary losses.
  • Defer NaMaster. NaMaster is still useful for later pure-B bandpower comparison, but it is not required before the current training run.
  • Keep weighted coefficient loss experimental. The current weighted loss uses human-assigned bounded weights. It should not replace MSE unless evaluation shows a clear gain.
  • Adaptive/self-weighted loss should be treated cautiously. If pursued later, prefer bounded validation-driven or uncertainty-weighted schemes over letting the model freely rewrite its objective during training.
  • Debugging does not imply file edits. Future debugging should report the mismatch first unless the user explicitly authorizes edits.
